# PSG 音声再生デモ (FM-7)

FM-7 の内蔵 PSG (AY-3-8910) **だけ**で音声 WAV を再生するデモです。FM 音源 (YM2203 / OPN) は使いません。
F-BASIC を経由しないディスク直接ブート形式で、電源投入 → ディスク挿入 → 起動だけで動きます。

- 起動すると `HIT SPACE KEY` が表示されます
- SPACE キーを押すと文字が `FM-7 PSG!` に変わり、PSG が音声でしゃべります (約 1.6 秒)
- しゃべり終わると `HIT SPACE KEY` に戻り、何度でも繰り返せます

PSG にサンプリング再生の専用機能はありません。ミキサでトーンとノイズを全て止め、**音量レジスタをサンプルごとに書き換える**ことで、PSG の音量 D/A 変換器 (対数カーブの 16 段) をそのまま DAC として使っています。

---

## 起動

`psgvoice.d77` をドライブ 0 に入れて電源を入れる (またはリセットする) だけです。F-BASIC のディスクである必要はありません。

ディスクを使わない場合は、カセットテープ (CMT) からもロードできます。後述の「[カセットテープからの起動 (make t77)](#カセットテープからの起動-make-t77)」を参照してください。

---

## 対応機種

| 機種 | 動作 | 備考 |
|------|------|------|
| FM-7 | 動作を確認済み | 内蔵 PSG (AY-3-8910) で鳴る |
| FM77AV | 動作を確認済み | `$FD0D`/`$FD0E` は YM2203 の SSG 部へのミラーなので、同じコードがそのまま鳴る |

画面はブート直後の 640x200 8色モードのまま使います。画面モードレジスタやアナログパレットには一切書き込まないため、機種による画面まわりの差異はありません。

## 画面遷移

```
   [起動] ──▶ HIT SPACE KEY (2倍角・白・中央寄せ)   ← SPACE 待ち
                    │ SPACE キーを押す
                    ▼
              FM-7 PSG! (2倍角・白・中央寄せ)
                    │ PSG 音量 DAC で音声再生 (約 1.6 秒、再生中はキーを見ない)
                    ▼
              HIT SPACE KEY                          ← 再表示して SPACE 待ちへ戻る (ループ)
```

文字の表示・消去はサブ CPU が行います。文字はサブ空間の CG ROM (`$D800`-、8x8 ドット、ASCII 配置) を 2 倍角に拡大して 3 プレーンへ書き (= 白)、消去は文字帯 (16 ライン x 全幅) の黒塗りです。

## カセットテープからの起動 (make t77)

ディスクを使わず、カセットテープ (CMT) からもロードできます。テープ用の次の 3 つは**同梱済み**です (`make t77` で `psgvoice.d77` から再生成もできます)。

| 同梱物 | 内容 |
|--------|------|
| `psgvoice.t77` | テープイメージ (FM-7 カセットテープイメージ形式)。対応エミュレータの CMT 入力に使う |
| `psgvoice.wav` | FSK 変調済みの音声 (44.1kHz / 16bit / モノラル)。実機のカセット入力やライン入力に使う |
| `psgvoice.cmt.txt` | F-BASIC 上でのロード手順テキスト |

変換にはリポジトリ共通のツール [`scripts/d77_to_t77_chunks.py`](../../scripts/d77_to_t77_chunks.py) (リポジトリルート側に同梱、MIT ライセンス) を相対参照で使うため、**リポジトリ一式の中で** `make t77` を実行してください。追加で Python 3 が必要です (標準ライブラリのみ)。

### ロード手順

F-BASIC (ROM BASIC) を起動し、テープ (T77 または WAV) を CMT 入力にセットしてから、`OK` プロンプトで次の 2 行を入力します。同梱の `psgvoice.cmt.txt` にも同じ手順が入っています。

```basic
CLEAR ,&H13FF
LOADM"CAS0:",,R
```

本体はテープ 1 本 = `LOADM` 1 回で読み込みが終わり、`,,R` の auto-exec で中継コード (トランポリン) が本体を `$0200`- へ展開し、テープ用エントリから起動します。以後の動作 (HIT SPACE KEY → SPACE で再生、ループ) はディスク起動と同じです。

### ディスク起動との違い

テープ起動は F-BASIC 稼働中 (warm start) からの突入なので、サブ CPU は BASIC のサブシステム処理の途中に居て、ディスク起動が前提とする「サブモニタのコマンド待ち」状態ではありません。そのためテープ用エントリ `TAPENT` (`$0200`) が、まずサブ CPU へ CANCEL (`$FD05` bit6) を発行して実行中の処理を中断させ、コマンド待ちループへ戻してから、ディスク版と同じ本体処理 (MAIN) へ合流します。FDC には一切触りません (ディスク起動ではこの前処理を通らないため、ディスク側の動作は変わりません)。

ディスクのセクタ配置は「IPL の 1 セクタ + 以降のセクタ連結 = `$0200` 起点の平坦なメモリ像」になるよう詰めてあり、`make t77` はこの D77 をそのまま単一チャンク (16KiB 1 回ロード) のテープへ変換します。仕組み (トランポリン・FSK 変調・T77 形式) の詳細はリポジトリルートの [`docs/CMT.md`](../../docs/CMT.md) を参照してください。

### テープロードの対応状況

| 機種 | 動作 | 備考 |
|------|------|------|
| FM-7 (F-BASIC 3.0) | 動作を確認済み | T77 / WAV (FSK 音声) の両入力で確認 |

## PSG 音量 DAC 再生の仕組み

### 原理

PSG の各チャネルの出力は「トーン (方形波) またはノイズ」を「音量レジスタの値」で増幅したものです。ミキサ (R7) でトーンとノイズを**両方とも止める**と、出力ゲートは開いたままになり、出力は音量レジスタの値だけで決まる直流レベルになります。

つまり音量レジスタ (R8/R9/R10) は、いつでも好きな値に書き換えられる **4 ビットの D/A 変換器**として使えます。これをサンプルごとに書き換えれば任意の波形を出せます。

PSG の音量特性は直線ではなく、1 段あたり約 3dB の**対数カーブ**です。そのため変換時 (`scripts/wav2psg.py`) には、波形の振幅をそのまま 16 等分するのではなく、「その音量値が実際に出す振幅」の表を引いて**最も近い出力が得られる音量値**を選びます (コンパンディング)。さらに量子化誤差を次のサンプルへ持ち越す誤差拡散で、16 段しかない DAC の歪みを聴感上減らしています。

### 再生ループ

メイン CPU (実効約 1.79MHz) で **1 サンプル = 163 サイクル**の固定サイクルループを回し、約 11kHz (データは 44100 の 1/4 = 11025Hz で作成、実効 11.0kHz) を維持します。再生中は割込みを一切受けないので、ループのサイクル数がそのままサンプル周期になります。

1 サンプルにつき R8/R9/R10 の 3 本へ同じ音量値を書きます (3 チャネル分の振幅 = 1 チャネルの 3 倍の音量が得られます)。書込み 1 回は 34 サイクルで、レジスタ番号のアドレスラッチとデータ書込みで構成します:

```
        lda     #8              ; 2   レジスタ番号
        sta     <$0E            ; 4   データポートへ
        lda     #$03            ; 2
        sta     <$0D            ; 4   アドレスラッチ
        clr     <$0D            ; 6   不活性へ戻す
        stb     <$0E            ; 4   音量値をデータポートへ
        lda     #$02            ; 2
        sta     <$0D            ; 4   データ書込み
        clr     <$0D            ; 6   不活性へ戻す
```

残りのサイクルは `exg a,a` (8 サイクル、無害) などで埋めて 163 サイクルちょうどに揃えます。

### PSG の I/O (メイン CPU 側)

| アドレス | 役割 |
|---------|------|
| `$FD0D` | コマンドポート。`$03`=アドレスラッチ / `$02`=データ書込み / `$01`=データ読出し / `$00`=不活性 |
| `$FD0E` | データポート (レジスタ番号 / 値) |

コマンドを書いた瞬間のデータポートの値が使われるため、**必ずデータを先に置いてからコマンドを書き**、各操作の後は `$00` (不活性) へ戻します。FM77AV ではこの 2 本のアドレスが YM2203 の SSG 部へのミラーになっているため、同じコードがそのまま動きます。

### 使用レジスタ

| レジスタ | 値 | 意味 |
|---------|-----|------|
| R7 (ミキサ) | `$3F` | トーン A-C とノイズ A-C を全て禁止 (= 音量レジスタが直流レベルになる) |
| R8/R9/R10 (音量) | 0-15 | 毎サンプル書き換える。再生していない間は 0 |

トーン周期 (R0-R5)・ノイズ周期 (R6)・エンベロープ (R11-R13) は一切使いません。

## 音声データ形式

`scripts/wav2psg.py` が `assets/fm7psg.wav` (44100Hz モノラル 16 ビット、約 1.6 秒) から生成します。

1. ローパスフィルタ (窓関数付き sinc) をかけてから 1/4 に間引き → 11025Hz
2. ピーク正規化し、各サンプルを 0..1 の目標振幅 (無音 = 0.5) に変換
3. PSG の対数音量特性の表を引き、最も近い出力になる音量値 0-15 へ量子化 (誤差拡散付き)
4. 2 サンプルを 1 バイト (上位ニブルが先) にパック

17698 サンプル → **8849 バイト** (`assets/psgdata.s`)。1.6 秒の音声がメイン RAM (`$1100`-`$3390`) に全量収まるので、再生中はディスクにも割込みにも一切触りません。

---

## キー入力

起動時に `$FD02` へ `$01` を書いてキーボードをメイン CPU 側へ解放し、`$FD03` の bit0 (0 でキーあり) をポーリングして `$FD01` から読みます。読んだコードが `$20` (SPACE) のときだけ反応し、それ以外は読み捨てます。CPU の割込みマスクは `orcc #$50` のままで、**割込みベクタは使いません**。再生中に押されていたキーは次の SPACE 待ちの前にまとめて読み捨てます。

## ビルド

ディスクイメージ `psgvoice.d77` は同梱済みで、そのまま起動できます。ソースを改変して作り直す場合は `make` を実行します。

```
make          # ソースから psgvoice.d77 を生成する
make t77      # psgvoice.d77 から CMT 用の T77 / WAV / 手順テキストを生成する
make clean    # 中間バイナリとテープ用生成物を削除する
```

必要なもの:

| ツール | 用途 | 備考 |
|--------|------|------|
| [lwtools](http://www.lwtools.ca/) の `lwasm` | 6809 アセンブル | `make LWASM=/path/to/lwasm` で場所を指定できます |
| Node.js | ディスクイメージ組み立て | `make NODE=/path/to/node` |
| Python 3 | `make t77` の変換と、音声データの再生成 (任意) | 標準ライブラリのみ。`make PYTHON=/path/to/python3` |

ビルドは 3 段階です。

1. `python3 scripts/wav2psg.py --wav assets/fm7psg.wav --out assets/psgdata.s --defs assets/psgdef.s`
   — 元の WAV から PSG 音量値データを生成
2. `lwasm` でメイン CPU 側 / サブ CPU 側 / 音声データをそれぞれアセンブル
3. `node scripts/mkd77.mjs` で 2D の D77 ディスクイメージを組み立て

`assets/psgdata.s` / `assets/psgdef.s` は生成済みのものを同梱しているので、Python が無い環境でも 2 と 3 だけでビルドできます。

## ディスク構成 (2D: 40シリンダ x 2サイド x 16セクタ x 256バイト)

通し番号 (LBA) = シリンダ x 32 + サイド x 16 + (セクタ - 1) とみなし、下記の位置へ 3 本のバイナリを並べます。

| 通し番号 | 物理位置 | 内容 | ロード先 |
|---------|---------|------|---------|
| 0 | シリンダ0 サイド0 セクタ1 | IPL | `$0100`-`$01FF` (ブート ROM が自動ロード) |
| 1-3 | シリンダ0 サイド0 セクタ2-4 | 本体 | `$0200`-`$04FF` |
| 4-15 | シリンダ0 サイド0 セクタ5-16 | サブ CPU 用プログラム | `$0500`-`$10FF` |
| 16-50 | シリンダ0 サイド1 セクタ1 - シリンダ1 サイド1 セクタ3 | PSG 音声データ 8849 バイト (連続配置) | `$1100`-`$3390` |
| その他 | — | 未使用 (`$E5` フィル) | — |

セクタ連結 (IPL の 1 セクタを除く) がそのまま `$0200` 起点の平坦なメモリ像に一致するよう詰めて配置してあります。`make t77` はこの性質を利用して、D77 をそのまま単一チャンクのテープイメージへ変換します。

ブート ROM はシリンダ0 サイド0 のセクタ1 だけを `$0100` へ読み込んでそこへジャンプします。残りは IPL 自身が FDC (MB8877 相当、`$FD18`-`$FD1F`) を直接操作し、読み込み表に従ってトラック単位で読み込みます (RESTORE 後、READ SECTOR を発行し `$FD1F` の DRQ/IRQ をポーリング。シリンダ1 へは自前で SEEK)。ブート ROM / ブート RAM 内のルーチンには依存しないため、ROM の版差異や機種差に影響されません。

音声データはメモリに全量ロードするので、再生開始後はディスクに触りません (モータも止めます)。

## メモリ配置

### メイン CPU 空間

| 範囲 | 内容 |
|------|------|
| `$0000`-`$00FF` | スタック |
| `$0100`-`$01FF` | IPL (ブート ROM が読み込む) |
| `$0200`-`$04FF` 付近 | 本体 (テープ用エントリ・サブ転送・SPACE 待ち・PSG 再生) |
| `$0500`-`$10FF` | サブ CPU 用プログラムの一時置場 (転送後は未使用) |
| `$1100`-`$3390` | PSG 音声データ (2 サンプル/バイト) |
| `$FC80`-`$FCFF` | 共有 RAM (サブ側 `$D380`-`$D3FF` に対応) |
| `$FD00`- | I/O |

### サブ CPU 空間

| 範囲 | 内容 |
|------|------|
| `$0000`-`$BFFF` | VRAM (640x200、B/R/G 3 プレーン、80 バイト/ライン) |
| `$C100`- | 文字表示プログラム (メインが転送) |
| `$CF80`- | スタックとワークエリア |
| `$D380`-`$D3FF` | 共有 RAM |
| `$D800`- | CG ROM (8x8 フォント) |

### 共有 RAM メールボックス

| メイン側 | サブ側 | 役割 |
|---------|--------|------|
| `$FC83` | `$D383` | 更新カウンタ (メインが指示の度に +1) |
| `$FC9D` | `$D39D` | リクエスト (1=`HIT SPACE KEY` / 2=`FM-7 PSG!`) |
| `$FC9E` | `$D39E` | リクエスト ack (処理した更新カウンタ値を返す) |
| `$FC9F` | `$D39F` | サブの初期描画完了マーカー (`$A5`) |

サブ CPU プログラムの転送・起動には、サブモニタの正規コマンド `$3F` (バイトコード実行: `$91`=メモリ転送 / `$93`=呼び出し / `$90`=終了) を使います。共有 RAM はデュアルポート調停のため、メイン側からのアクセスは全て HALT (`$FD05`) で包みます。
