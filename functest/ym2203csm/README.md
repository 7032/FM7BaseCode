# YM2203 CSM 音声合成デモ (FM77AV / AV40系)

FM77AV 内蔵の FM 音源 (YM2203 / OPN) の **CSM 音声合成モード**を使って、サンプリング音声ではなく「フォルマント合成」で人の声を鳴らすデモです。
F-BASIC を経由しないディスク直接ブート形式で、電源投入 → ディスク挿入 → 起動だけで動きます。

- FM77AV系で起動すると、320x200 の 64 色画像が画面いっぱいに表示されます
- 画像の上に `PUSH ANY KEY` が黄色で重ねて出ます
- 何かキーを押すと `PUSH ANY KEY` が消え (下の画像はそのまま残ります)、 音声で「エフエムセブンセブンエーブイ」としゃべります
- 鳴り終わると再び `PUSH ANY KEY` が出て、何度でも繰り返せます

音声データは PCM ではありません。元の波形を 10.1725 ms ごとに分析して求めた **基本周波数 (ピッチ) と 4 本のフォルマント (周波数 + 振幅)** だけを持っており、2.95 秒の音声がわずか 4 KB 弱 (14 バイト x 290 フレーム = 4060 バイト) に収まっています。

---

## 起動

`ym2203csm.d77` をドライブ 0 に入れて電源を入れる (またはリセットする)だけです。F-BASIC のディスクである必要はありません。

## 対応機種

| 機種 | 動作 | 画面モード | 音 |
|------|------|-----------|----|
| FM77AV | 画像 + 音声デモが動く | 320x200 4096色 | 鳴る |
| FM77AV29/40 | 画像 + 音声デモが動く (FM77AV と同一) | 320x200 4096色 | 鳴る |
| FM77AV20EX/40EX/40SX | 画像 + 音声デモが動く (FM77AV と同一) | 320x200 4096色 | 鳴る |
| FM-7 | **非対応**。`SORRY! IT'S FOR FM77AV!` を表示して停止 | 640x200 8色 (ブート直後のまま) | 鳴らさない |

- FM-7 では `$FD12` / `$FD04` / アナログパレット (`$FD30`-`$FD34`) / `$D42F` に 一切書き込みません。ブート直後の 640x200 8色のまま非対応メッセージを出し、 OPN へも 1 バイトも書かずに停止します。**画像データのセクタも 1 つも  読みません** (画像を読むのは機種判別で AV 系と分かった後だけ)。

機種判別は、ブート直後 (640 モード) にメイン CPU から `$FD12` を読んで行います。AV 系は bit6=0 を返し、FM-7 は当該レジスタが未実装でオープンバス (`$FF`、bit6=1)になることを利用しています。

## 画面遷移

```
   [起動] ──▶ 画像を全画面表示 (320x200 64色)
              PUSH ANY KEY (2倍角・黄、画像の上に重ね書き)  ← 入力待ち
                    │ 何かキーを押す
                    ▼
              画像はそのまま
              (PUSH ANY KEY の下に隠れていた画像を書き戻して消去)
                    │ CSM 音声再生 (2.95 秒、再生中はキーを見ない)
                    ▼
              画像 + PUSH ANY KEY               ← 再表示して入力待ちへ戻る (ループ)
```

- 消去は**黒塗りではありません**。文字が隠す矩形 (24 バイト列 x 16 ライン x 6 プレーン = 2304 バイト) の元データを画像展開中にメイン RAM へ退避しておき、消去時にそれを書き戻します。したがって消去後の画像は元どおりになります。
- 再生中に押されていたキーは、次の `PUSH ANY KEY` 表示指示より**前**に読み捨てます (表示完了を待ってから捨てると、描画中の打鍵を取りこぼすため)。

### FM77AV 系 (320x200 4096色)

`$FD12` の bit6 を 1 にして 320x200 4096色モードにし、アナログパレット(`$FD30`-`$FD34`) には**画像に付属する 64 エントリ**を設定します。
このモードの VRAM はページ 0/1 (`$D430` bit5) x 各 6 面 = 12 サブプレーンで、本デモは**ページ 0 の 6 面だけ**を使い (1 ドット 6 ビット = 64 色)、ページ 1 は 0 のままにします。

| 表示 | 内容 | 拡大率 | 位置 | 色 |
|------|------|-------|------|----|
| 背景 | 320x200 の 64 色画像 | 等倍 (全画面) | 全面 | パレット 64 色 |
| 案内 | `PUSH ANY KEY` | 2 倍角 (16x16 ドット/文字) | 左端 32 ドット / 上端 184 ライン (192x16 ドット) | 黄 `#FFFF00` (パレット添字 `IMGTXTCOL` = 31) |

### FM-7 (640x200 8色)

画面モードは切り替えず、ブート直後の 640x200 8色 (B=`$0000` / R=`$4000` / G=`$8000`、80 バイト/ライン) のまま `SORRY! IT'S FOR FM77AV!` を 2 倍角・中央寄せ (左端 136 ドット / 上端 92 ライン) で表示して停止します。
文字はサブ空間の CG ROM (`$D800`-、8x8、1 文字 8 バイト、ASCII 配置) の字形を整数倍に拡大して描いています。開始桁をバイト境界に揃えているのでビットシフトは不要で、1 ドットを N ドットへ広げる表引きだけで済みます。

## 全画面画像の表示 (AV 系のみ)

### データ形式

`assets/fm77av_img.s` (`scripts/png2fm77av.py` が `assets/FM77AV.PNG` から生成)
は次の 3 つを持っています。

| ラベル | 内容 |
|--------|------|
| `imgpal` | アナログパレット 64 エントリ x 5 バイト。先頭から `$FD30`(添字上位4bit) / `$FD31`(添字下位8bit) / `$FD32`(青) / `$FD33`(赤) / `$FD34`(緑) の順にそのまま書けばよい並び |
| `imgtxtcol` | 重ね書き文字の色 (パレット添字 `IMGTXTCOL`) 1 バイト |
| `imgdata` | 6 プレーン (B3/B2/R3/R2/G3/G2 = サブ窓 `$0000`/`$2000`/`$4000`/`$6000`/`$8000`/`$A000`) を連結した 48000 バイトを 1 本の RLE ストリームに圧縮したもの (36707 バイト、76.5%) |

- 元画像はパレット画像で実色数が 62 色なので、**色を量子化していません**。
  誤差は 1 チャネル 8 ビット → 4 ビットの丸めだけです (PSNR 34.18 dB、平均色差 8.28)。
- 64 スロットのうち 1 つが空くので、そこに**黄 (`#FFFF00` = RGB4 `FF0`)** を置いて文字色 (`IMGTXTCOL` = 31) にしています。画像のどのドットもこの添字を使っていないため、文字を重ねても画像の発色は一切変わりません。文字色は `python3 scripts/png2fm77av.py --text-color RRGGBB` で差し替えられます。 空きスロットの色を書き換えるだけなので、色を変えても `imgdata` (画像本体のRLE ストリーム) は 1 バイトも変わりません。
- RLE は「制御バイト C が `$00`=終端 / bit7=1 なら次の 1 バイトを (C&$7F) 回 / bit7=0 なら続く C バイトをそのまま」という単純な形式です。トークンはプレーン境界 (8000 バイト) をまたぎます。
- パレット添字の割当 (どの色を何番に置くか) は**圧縮率が最小になるように山登り法で最適化**してあります (42380 → 36707 バイト)。乱数種と反復回数を固定しているので、何度生成しても同じデータになります。

### 読み込みと転送

圧縮後でも 36 KB 近くあり、メイン RAM に丸ごと置く余地はありません。そこで**ディスクから 1 セクタずつ読みながら逐次 RLE 展開し、80 バイト (= 2 ライン)ずつサブ CPU へ渡して VRAM へ書かせる**方式にしています。

- メイン RAM に必要なのは 512 バイトのセクタバッファと 80 バイトのチャンクバッファだけです。`$8000` 以降を RAM に切り替える必要もありません。
- 画像を読むのは機種判別の後なので、FM-7 では 1 セクタも読みません。
- 8000 (1 プレーン) は 80 で割り切れるので、チャンクがプレーン境界をまたぐことはありません。
- 転送中の画面には上から順に画像が現れていきます (ページ 0 に直接書くため)。

**セクタのインターリーブ**: FDD は 300rpm (1 周 200ms、1 セクタ枠 12.5ms) で回り続けています。1 セクタ読むごとに展開と転送で約 20ms かかるため、セクタを連番で並べると次を要求する頃には目的の枠を通り過ぎていて、毎回 1 回転 (200ms) 待たされます (145 セクタで 29 秒以上)。そこで画像領域は**3 枠おき (インターリーブ 3、37.5ms)** に配置してあります(`scripts/mkd77.mjs` の `IMG_ORDER` と `src/csmdemo.asm` の `ISEQT` が対)。これで画像の読込・展開・表示は**約 6.0 秒** (電源投入からは約 7.8 秒) で完了します。

### サブ CPU への転送手順 (BLIT)

サブ CPU 側のプログラムは共有 RAM のリクエストセルを監視していて、`SH_REQ=3` で「ペイロードを指定プレーンの指定オフセットへ置く」BLIT を行います。文字の消去 (退避した画像の書き戻し) も同じ BLIT で行います。
取りこぼしが原理的に起きないよう、二重に確認しています。

1. **HALT の確立確認** — 共有 RAM はサブ CPU が HALT している間しかメイン側から読み書きできません。`$FD05` の bit7 を待つだけでなく、プローブセルへ `$A5` を書いて読み戻し、一致するまで待ちます (掴めていないと書込みは落ち、読出しは `$FF` になります)。
2. **書込みの読み戻し** — シーケンス値と長さを書いた直後に読み戻して照合し、食い違ったら同じシーケンス値のまま最初から書き直します。
3. サブ側は受け取ったシーケンス値が「前回 +1」でなければ `SH_IERR` を増やし、 BLIT したバイト数を `SH_ICNT` に積みます (メイン側から事後照合できます)。ack (`SH_RACK`) が返るまでメインは次のリクエストを出さないので、ペイロードが上書きされることはありません。

## CSM 音声合成の仕組み

YM2203 の **CSM (Composite Sinusoidal Modeling) モード**は、チャネル 3 を「4 オペレータ独立周波数 + タイマ A によるキーオン自動繰り返し」にする機能です。

- **タイマ A = ピッチ**。タイマ A がオーバーフローするたびにチャネル 3 の全オペレータがキーオフ → キーオンされます。このときオペレータの **位相が 0 にリセット**され、4 本の正弦波が同時に立ち上がります。この繰り返し周期がそのまま**声の基本周波数 (F0)** になります。
- **4 オペレータ = フォルマント**。各オペレータの周波数が声道の共振 (フォルマント) に対応します。アルゴリズム 7 (4 オペレータ並列・変調なし)  なので、出力は 4 本の正弦波の単純加算です。
- **TL = 振幅**。各オペレータの TL (トータルレベル) がフォルマントの強さです。
- **フレーム周期 10.1725 ms**。メイン CPU の周期タイマを 5 回数えるごとにピッチとフォルマント (周波数 + 振幅) を書き替えます (下記)。

つまり「ピッチ周期でパルスを立て、その音色を 4 本のフォルマントで形づくる」という、人の発声のモデルをそのままハードウェアで実現しています。

### フレーム同期の時間源 — メイン CPU の周期タイマ

フレームの刻みには **OPN のタイマではなくメイン CPU 側の周期タイマ**を使います。

| ポート | 役割 |
|--------|------|
| `$FD02` (W) | IRQ 許可。bit0=キーボード / **bit2=周期タイマ**。本デモは `$05` を書く |
| `$FD03` (R) | IRQ 要因フラグ (active-low: 0=発生)。bit0=キーボード / **bit2=周期タイマ** |

- 周期は **約 2.0345 ms (491.52 Hz)**。`$FD03` を読むとタイマのフラグが落ちるので、1 回読むごとに 1 tick を消費したことになります。
- **1 フレーム = 5 tick = 10.1725 ms** (98.304 フレーム/秒)。
- CPU の割込みマスクは `orcc #$50` のままで、**割込みベクタは一切触りません**。フラグをポーリングするだけなので、ベクタが RAM か ROM かに依存しません。
- キーボードのフラグも同じ `$FD03` に出ますが、`$FD03` の読出しでは落ちません(落とすには `$FD01` を読む)。再生中はキーを見ないので無視して構いません。 再生後に `PUSH ANY KEY` を出す前へ、まとめて読み捨てています。

### ピッチ (タイマ A) の求め方

OPN のタイマクロックは 1.2288 MHz、プリスケーラは 1/6 です。

```
タイマ A 周波数 [Hz] = 1228800 / (72 x (1024 - NA)) = 17066.667 / (1024 - NA)
```

- ピッチ: `NA = 1024 - 17066.667 / F0`。`$24` に `NA>>2`、`$25` に `NA&3` を書く
- タイマ B (`$26`/`$27` bit1) は**一切使いません** (周期も設定しません)

フォルマント周波数は F-Number で与えます。

```
f [Hz] = fnum x 2^block x MUL / 122.88
$AC 系 (高位) = (block << 3) | ((fnum >> 8) & 7)     $A8 系 (低位) = fnum & $FF
```

MUL=1 では 2132 Hz が上限で高いフォルマントに届かないため、本デモは全スロット **MUL=2** で固定しています (音声パラメータ生成側の周波数換算と対になっているので、片方だけ変えるとフォルマントがずれます)。

### レジスタ設定 (再生開始時に 1 回)

書く順序も含めて次のとおりです (この順序を守ってください)。

| レジスタ | 値 | 意味 |
|----------|-----|------|
| `$2F` | (番地選択のみ) | プリスケーラ 1/2 (ラッチをいったん落とす) |
| `$2D` | (番地選択のみ) | プリスケーラ 1/6 (タイマ周期の基準を確定) |
| `$27` | `$30` | 通常モード / 両タイマ停止 / 両フラグクリア |
| `$28` | `$00`,`$01`,`$02` | 全チャネル キーオフ |
| `$07` | `$BF` | SSG のトーン / ノイズを全停止 |
| `$08,$09,$0A` | `$00` | SSG 音量 0 |
| `$B2` | `$07` | チャネル3 フィードバック 0 / アルゴリズム 7 |
| `$32,$36,$3A,$3E` | `$02` | DT=0 / MUL=2 |
| `$52,$56,$5A,$5E` | `$1F` | KS=0 / AR=31 (立ち上がり瞬時) |
| `$62,$66,$6A,$6E` | `$00` | AM=0 / DR=0 |
| `$72,$76,$7A,$7E` | `$1F` | SR=31 (最速減衰) |
| `$82,$86,$8A,$8E` | `$0F` | SL=0 / RR=15 |
| `$92,$96,$9A,$9E` | `$00` | SSG-EG 無効 |
| `$42,$46,$4A,$4E` | `$7F` | TL 最小音量 (再生開始まで無音) |
| `$24,$25` | 先頭フレームの値 | タイマ A (先頭フレームのピッチ) |
| `$27` | `$81` | **CSM モード + タイマ A ロード/スタート** |

#### `$27` の bit7-6 は 2 ビットの「モード番号」です

`$27` のビット割付は **bit7-6=Ch3 のモード番号 / bit5,bit4=タイマ B,A のフラグクリア / bit3,bit2=タイマ B,A のフラグ許可 / bit1,bit0=タイマ B,Aスタート**です。

ここで **bit7 と bit6 は独立した 2 つの許可ビットではなく、ひとつの2 ビットのモード番号**です。

| bit7-6 | モード |
|:---:|---|
| `00` | 通常モード |
| `01` | Ch3 特殊モード (3 スロット独立 F-Number) |
| `10` | **CSM モード** (3 スロット独立 F-Number を含む) |
| `11` | 未定義 (禁止) |

したがって **CSM を使うときの bit7-6 は `10` ちょうど**でなければならず、`$27` に書く値は必ず `(値 & $C0) == $80` を満たす必要があります。

## 音声データ形式 (1 フレーム 14 バイト)

`assets/csmdata.s` は 14 バイト x `CSMFRAMES` (290) フレームの `fcb` 列です。1 フレームの並びと書込み先レジスタは次のとおりです(`src/csmdemo.asm` の `REGTB` と 1:1 対応)。

| バイト | 内容 | 書込み先 |
|-------|------|---------|
| 0, 1 | タイマ A (ピッチ) 上位 / 下位 | `$24` / `$25` |
| 2, 3 | フォルマント1 F-Number 上位 / 下位 | `$AD` / `$A9` |
| 4, 5 | フォルマント2 F-Number 上位 / 下位 | `$AC` / `$A8` |
| 6, 7 | フォルマント3 F-Number 上位 / 下位 | `$AE` / `$AA` |
| 8, 9 | フォルマント4 F-Number 上位 / 下位 | `$A6` / `$A2` |
| 10-13 | フォルマント1-4 の TL (音量、小さいほど大音量 / `$7F`=無音) | `$42` / `$46` / `$4A` / `$4E` |

### 1 フレームの処理

1. `$FD03` の bit2 を 5 回ポーリングして 5 tick (= 10.1725 ms) 待つ(1 tick ごとにウォッチドッグ付き)
2. `$27` に `$B1` を書く (bit7-6=`10` で CSM モード維持 + bit5,bit4 で両タイマのフラグをクリア + bit0 でタイマ A 継続)。bit0 は 1→1 なので再ロードは起きず、ピッチの周期は途切れません
3. 上表の 14 バイトを OPN へ書く

守るべき約束が 4 つあります。

- F-Number は**上位バイトを先に、下位バイトを後に**書きます(下位バイトの書込みで値が確定するラッチ構造のため)。
- 各フォルマントの周波数と TL は必ず同じオペレータへ送ります。
- **`$27` に `$00` を書いてはいけません**。タイマがリロードされてキーオンが欠落し、ピッチが乱れます。必ずタイマ A の有効ビット (bit0) を保ったまま書きます。
- **再生中に `$27` へ書く値はすべて `(値 & $C0) == $80` を満たすこと**。途中の 1 回でも bit6 を立ててしまうと、その瞬間から CSM が成立しなくなります。

CSM 中の TL 書込みはラッチされ、**次のキーオン (ピッチ周期の頭) で一斉に反映**されます。そのためフレーム途中で書き換えても波形に段差が出ません。
再生が終わったら `$27`←`$30` (bit7-6=`00` = 通常モードへ戻す・タイマ停止・bit5/bit4 で両フラグクリア)、チャネル 3 をキーオフ (`$28`←`$02`)、TL を最小 (`$42/$46/$4A/$4E`←`$7F`) にして完全な無音に戻します。

### レジスタ書込みの手順

OPN は `$FD15` (コマンドポート) と `$FD16` (データポート) の 2 本で操作します。

```
$FD16 ← レジスタ番号
$FD15 ← $03      ; ADDRESS
$FD15 ← $00      ; INACTIVE
(短い空ループで整定待ち)
$FD16 ← 値
$FD15 ← $02      ; WRITEDAT   ← ここで実際に書き込まれる
$FD15 ← $00      ; INACTIVE
(短い空ループで整定待ち)
```

- **各コマンドの後に必ず `$00` (INACTIVE) を書いてラッチを解除**します。
- 整定待ちは 7 回の空ループ (1 回 5 サイクル) です。
- **ステータス (READSTAT) は一切読みません**。読出し手順やビジービットの扱いは実装差が出やすく、依存させない方が機種を問わず確実に通るためです。

1 回の書込みは約 110 サイクル (1.794 MHz で約 61 マイクロ秒)。1 フレーム15 回で約 1650 サイクル = **約 0.92 ms** となり、フレーム周期 10.1725 ms の1 割弱で収まります。

なお OPN のタイマフラグを落とせるのは `$27` の bit4 / bit5 への書込みだけで、ステータスを読んでもクリアされません。本デモはフラグを読みませんが、毎フレームの `$27`←`$B1` でクリアし続けています。

また、プリスケーラ (`$2D`-`$2F`) は「アドレスを選ぶ」だけで効くレジスタです。アドレスラッチの時点で発火する実装と、データ書込みの時点で発火する実装があるため、本デモは他のレジスタと同じく**アドレスと値の両方を書いて**います(どちらの実装でも確実に通ります)。

---

## キー入力

起動時に `$FD02` へ `$05` を書いて、キーボード (bit0) とメイン CPU の周期タイマ(bit2) の両方をメイン CPU 側へ解放し、`$FD03` の bit0 (0 でキーあり) をポーリングして `$FD01` から読みます。CPU の割込みマスクは `orcc #$50` のままで、**割込みベクタは使いません**。離鍵で発生するブレークコード (bit7 が立つ) は押下と区別して無視します。

## ビルド

ディスクイメージ `ym2203csm.d77` は同梱済みで、そのまま起動できます。ソースを改変して作り直す場合は `make` を実行します。

```
make          # ソースから ym2203csm.d77 を生成する
make image    # assets/fm77av_img.s を assets/FM77AV.PNG から作り直す
make clean    # 中間バイナリを削除する
```

`assets/fm77av_img.s` は**既定では再生成しません**。パレット割当の山登り最適化に 1-2 分かかるためで、作り直したいときだけ `make image` を実行してください (乱数種と反復回数は固定なので、同じ PNG からは常に同じデータが出ます)。
重ね書き文字の色だけを変えたいときは、変換スクリプトを直接呼びます。

```
python3 scripts/png2fm77av.py --input assets/FM77AV.PNG \
    --out assets/fm77av_img.s --text-color FFFF00
```

`--text-color` は画像が使っていない空きパレットスロットへ置く色を変えるだけなので、色を変えても `imgdata` (画像本体の RLE ストリーム) は 1 バイトも変わりません (`imgpal` の該当 1 エントリだけが変わります)。

必要なもの:

| ツール | 用途 | 備考 |
|--------|------|------|
| [lwtools](http://www.lwtools.ca/) の `lwasm` | 6809 アセンブル | `make LWASM=/path/to/lwasm` で場所を指定できます |
| Node.js | ディスクイメージ組み立て | `make NODE=/path/to/node` |
| Python 3 + NumPy + SciPy | 音声パラメータの再生成 (任意) | `make PYTHON=/path/to/python3` |
| Python 3 + NumPy + Pillow | 画像データの再生成 (任意、`make image` のときだけ) | 同上 |

ビルドは 3 段階です。

1. `python3 scripts/wav2csm.py --wav assets/FM77AV.wav --out assets/csmdata.s`
   — 元の WAV から CSM パラメータ (`assets/csmdata.s`) を生成
2. `lwasm` でメイン CPU 側 / サブ CPU 側 / 画像データをそれぞれアセンブル
3. `node scripts/mkd77.mjs` で 2D の D77 ディスクイメージを組み立て

`assets/csmdata.s` と `assets/fm77av_img.s` は生成済みのものを同梱しているので、Python / NumPy / SciPy / Pillow が無い環境でも 2 と 3 だけでビルドできます(`wav2csm.py` が存在しない場合も同様に、同梱の `assets/csmdata.s` をそのまま使います)。

## ディスク構成 (2D: 40シリンダ x 2サイド x 16セクタ x 256バイト)

通し番号 (LBA) = シリンダ x 32 + サイド x 16 + (セクタ - 1) とみなし、
下記の位置へ 3 本のバイナリを並べます。

| 通し番号 | 物理位置 | 内容 | ロード先 |
|---------|---------|------|---------|
| 0 | シリンダ0 サイド0 セクタ1 | IPL | `$0100`-`$01FF` (ブート ROM が自動ロード) |
| 1-15 | シリンダ0 サイド0 セクタ2-16 | 本体 + 音声データ | `$0200`-`$10FF` |
| 16-31 | シリンダ0 サイド1 セクタ1-16 | 本体 + 音声データ (続き) | `$1100`-`$20FF` |
| 32-43 | シリンダ1 サイド0 セクタ1-12 | サブ CPU 用プログラム | `$2100`-`$2CFF` |
| 64-208 | シリンダ2 サイド0 - シリンダ6 サイド1 | 画像データ 145 セクタ (パレット 320 + 文字色 1 + RLE 36707 = 37028 バイト) | メモリには置かず 1 セクタずつ読んで展開 |
| その他 | — | 未使用 (`$E5` フィル) | — |

ブート ROM はシリンダ0 サイド0 のセクタ1 だけを `$0100` へ読み込んでそこへジャンプします。残りは IPL 自身が FDC (MB8877 相当、`$FD18`-`$FD1F`) を直接操作して読み込みます (RESTORE 後、READ SECTOR を発行し `$FD1F` のDRQ/IRQ をポーリング)。シリンダ1 へは IPL が自前で SEEK を発行します。
ブート ROM / ブート RAM 内のルーチンには依存しないため、ROM の版差異や機種差に影響されません。

画像データ (シリンダ2 以降) は本体が同じ FDC ルーチンで読みます。
シーク・サイド切替も自前です。**トラック内の並びだけは 3 枠おきのインターリーブ**で、読み出し順は

```
1, 4, 7, 10, 13, 16, 3, 6, 9, 12, 15, 2, 5, 8, 11, 14
```

です (`scripts/mkd77.mjs` の `IMG_ORDER` = `src/csmdemo.asm` の `ISEQT`)。
1 セクタ読むごとに RLE 展開とサブ CPU への転送で約 20ms かかるため、連番だと毎回ディスク 1 回転 (200ms) を待つことになるのを避けています。

## メモリ配置

### メイン CPU 空間

| 番地 | 内容 |
|------|------|
| `$0100`-`$01FF` | IPL (FDC 直接操作によるローダ。SEEK/READ SECTOR は本体からも使う) |
| `$0200`-`$07C0` | 本体プログラム (機種判別・画面初期化・サブ転送・画像展開・CSM 再生) |
| `$07C1`-`$07EA` | ワークエリア |
| `$07EB`-`$17C6` | 音声パラメータ `csmdata` (14 バイト x 290 フレーム = 4060 バイト) |
| `$2100`-`$2CFF` | サブ CPU 用プログラムのイメージ (転送後は未使用) |
| `$2D00`-`$2EFF` | 画像データのセクタバッファ (512 バイト) |
| `$3000`-`$38FF` | `PUSH ANY KEY` が隠す矩形の元画像 (6 面 x 16 ライン x 24 バイト = 2304) |
| `$3900`-`$394F` | サブへ送るチャンクバッファ (80 バイト = 2 ライン) |
| `$3F00` | スタックポインタ初期値 |
| `$FC80`-`$FCFF` | 共有 RAM (サブ CPU の `$D380`-`$D3FF` に対応) |

### サブ CPU 空間

| 番地 | 内容 |
|------|------|
| `$0000`-`$BFFF` | VRAM (ページ 0/1 x 6 面、`$D430` bit5 で切替) |
| `$C100`- | 描画プログラム (メインから転送される) |
| `$CF80` | スタックポインタ初期値 |
| `$CF90`-`$CFB7` | 描画用ワークエリア |
| `$D380`-`$D3FF` | 共有 RAM |
| `$D800`-`$DFFF` | CG ROM (8x8 フォント) |

### 共有 RAM メールボックス

| メイン | サブ | 内容 |
|--------|------|------|
| `$FC82` | `$D382` | サブモニタのコマンドバイト (ブート時のみ) |
| `$FC83` | `$D383` | 更新カウンタ (メインが指示の度に +1) |
| `$FC84` | `$D384` | 重ね書き文字の色 (パレット添字 `IMGTXTCOL`) |
| `$FC85` | `$D385` | BLIT: 書込み先プレーン番号 (0-5) |
| `$FC86`/`$FC87` | `$D386`/`$D387` | BLIT: プレーン内オフセット |
| `$FC88` | `$D388` | BLIT: バイト数 (8 の倍数。画像 80 / 文字消去 24) |
| `$FC89` | `$D389` | サブが検出した異常の件数 (0 が正常) |
| `$FC8A` | `$D38A` | 機種フラグ (0=FM-7 / 1=AV 系) |
| `$FC8B`/`$FC8C` | `$D38B`/`$D38C` | サブが BLIT で書いた総バイト数 (照合用) |
| `$FC8B`-`$FC99` | `$D38B`-`$D399` | 転送用バイトコード領域 (ブート時のみ) |
| `$FC9A` | `$D39A` | HALT 確立確認用のプローブセル |
| `$FC9B`/`$FC9C` | `$D39B`/`$D39C` | 転送のシーケンス値 / ack (ブート時のみ) |
| `$FC9D` | `$D39D` | リクエスト (1=`PUSH ANY KEY` 表示 / 3=BLIT) |
| `$FC9E` | `$D39E` | リクエストの ack |
| `$FC9F` | `$D39F` | サブの初期描画完了マーカー (`$A5`) |
| `$FCA0`-`$FCFF` | `$D3A0`-`$D3FF` | ペイロード (ブート時 96 バイト / BLIT 時は最大 80 バイト) |

サブ CPU 側プログラムの転送・起動には、サブモニタの正規コマンド `$3F`(バイトコード列の解釈: `$90`=終了 / `$91` src,dst,len=転送 / `$92` addr=分岐 / `$93` addr=呼出) を使っています。ROM 版に依存する内部番地を仮定しないため、FM-7 と FM77AV 系のどちらでも同じ手順で動きます。
起動後はサブモニタが動いていないので、ブート時にだけ使うセル(バイトコード領域・ペイロード) は BLIT 用に流用しています。
共有 RAM はデュアルポート調停のため、メイン側からのアクセスはすべてサブ CPU の HALT (`$FD05`) で挟み、さらにプローブセルの書込み/読出しで**本当に掴めたか**を確かめてから書いています。
